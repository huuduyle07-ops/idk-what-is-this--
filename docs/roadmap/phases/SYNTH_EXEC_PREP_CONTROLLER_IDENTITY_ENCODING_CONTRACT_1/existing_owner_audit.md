# Existing owner convention audit

Pure source review for SYNTH.EXEC.PREP.CONTROLLER.IDENTITY.ENCODING.CONTRACT.1. No owner module was imported, no owner was issued, and no operational effect was performed. Existing owner source is unchanged. All authority remains false.

## Existing generators and authentication

Every audited dynamic authorization, runtime lease, provider proof/context, reflection admission and reflection lease ID is generated by `secrets.token_hex(32)`: exactly 64 lowercase ASCII hex bytes representing 256 requested random bits. This is a historical allocation convention. The sources do not make possession of those scalar IDs sufficient authentication.

Weak registries also do not by themselves prove permanent nonreuse after collection. Future requirements must freeze deterministic collision and tombstone rules independently of these conventions.

## What stops each threat

| Threat | Scalar encoding's contribution | Actual authentication or lifecycle barrier |
|---|---|---|
| Accidental collision | Random 256-bit allocation makes accidental collision improbable; canonical grammar rejects alternate forms. | Locked collision check plus allocation without reuse is needed for a strict uniqueness contract. |
| Guess another live ID | Randomness makes guessing improbable but is not relied upon as authority. | Exact original-object identity in the selected private registry entry; an ID-only presentation cannot satisfy it. |
| Replay stale ID | Width and randomness do not reject stale state. | Original-object retention, authenticated current state and permanent one-shot/tombstone maps reject duplicate issuance or reopening. |
| Cross-process copy or fork | Scalar bytes are freely copyable. | Issuing PID check, process-local secret and registry/original-object continuity; pinned lifecycle rejects foreign PID before touching inherited lock. |
| Cross-owner substitution | Hex grammar alone does not separate owners. | Exact class, owner/phase/schema domain, separate registry, retained upstream graph and domain-separated HMAC. |
| Forged same-process dataclass with copied IDs | Every valid scalar can be copied. | `record["object"] is value` or exact weakref result `is value`; HMAC and immutable projection checks independently remain required. |
| PID reuse after restart | No scalar-width defense is sufficient by itself. | New process has fresh private secret and registry; no original authoritative object continues into it. PID is one binding component, never the whole namespace proof. |
| Registry reuse after terminal state | Grammar has no terminal-state knowledge. | Permanent upstream-to-issuance map, retained ID records and authenticated terminal state; allocation cannot recycle their keys. |
| ID reuse after tombstone | A new random value is not a tombstone policy. | Future allocator must forbid reassignment of all reserved IDs, including dead handles and terminal/tombstone entries, until the retained namespace ends. |
| Serialization, reconstruction or JSON copy | Strings round-trip as strings only. | Exact original-object/registry requirements reject reconstructed values; `as_dict` returns report projections, not authority. |
| Wrapper or subclass | A copied field can satisfy scalar grammar. | Validators use `type(value) is ExactClass`, followed by exact original-object identity. |

These checks model callers that can present values, copies and substituted objects through public interfaces. They do not purport to isolate an adversary with arbitrary mutation of owner-private memory, replacement of validation code or control of the interpreter.

## ID, fingerprint, HMAC and capability are separate

Pinned owner `stable_fingerprint` values are 64 lowercase hex SHA256 digests over domain-separated immutable issuance projections (`core/synthetic_runtime_authorization_pinned_lifecycle.py:364-380`, `core/synthetic_reflection_execution_admission_pinned.py:442-454`, `core/synthetic_reflection_execution_lifecycle_pinned.py:517-533`). HMAC is separately computed over the private retained projection and, for lifecycle owners, its current state (`:359-361`, `core/synthetic_reflection_execution_admission_pinned.py:105-107`, `core/synthetic_reflection_execution_lifecycle_pinned.py:122-124`). The 32-byte process-local HMAC secrets are created independently from IDs. A fingerprint is not a secret, and a scalar handle is not a signature or capability.

No audited public validation path confers authority from ID possession alone. The source therefore supports a non-secret future scalar whose work is stable lookup, correlation and uniqueness, provided the exact original object, private registry, authenticated domain/PID/graph and permanent lifecycle semantics remain mandatory. There is no semantic requirement here to spend 256 random bits on every future scalar. Shorter deterministic counters can be truthful if atomic allocation, owner/domain separation, no wrap/reset/rollback, fail-closed exhaustion and permanent no-reuse records are frozen. Guessability is then irrelevant to authentication; it does not become a credential merely because it selects a registry key.

That conclusion cannot authorize a string-only endpoint that resolves a guessed scalar into usable authority. A future transport admission must authenticate the owning relation before a request/operation ID is used for dispatch or replay lookup, and it must retain domain/operation equality. A newly introduced bearer boundary would require a new security analysis. This audit does not select an encoding, implement a generator or revise existing owners.
